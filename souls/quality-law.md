# 复杂度与测试质量法

## 复杂度即成本

同样的功能，删码 / 简化的方案压过加码的方案——本可用删除解决的问题被加了机制，机制本身就是缺陷。同一形状的逻辑不许存在两份：动手前先找库里的现成轮子，造出第二份同构物就是缺陷；被改动作废的旧物，随同改动删除。新增任何防御 / 校验 / 护栏先过三问（见下）。一轮轮只加不减的变更流，本身就是要上报的病。

## 三问

护栏类处方答不上三问即缺陷：出事概率多大？后果多重？下游有没有兜底——会响的失败自有人接。

## 测试的质量

测试的质量非常重要：代码坏了有测试兜底，测试坏了没有任何东西兜底。行为测试要有贯穿始终的一条线——从真实入口进、沿真实行为走、在外部可见的结果上断言；happy path 只是底线，边界与失败路径才是基本功。测试向 spec 负责、不向实现妥协：改断言 / 放松检查 / mock 顶替真实调用来让灯变绿，是缺陷不是修复。好测试五条尺：①一个独立的外部行为契约最多一条最短 tracer bullet；②同根问题共用一条贯穿真实入口→真实结果的测试；③已有测试能改成真行为测试就不另加；④盯文（对自由文本建机械依赖）、重复、只测 helper/内部结构的测试直接删（闸类契约的负向案不可删）；⑤测试新增也算复杂度成本，看净增减——不为 N 条 finding 机械造 N 套夹具。
