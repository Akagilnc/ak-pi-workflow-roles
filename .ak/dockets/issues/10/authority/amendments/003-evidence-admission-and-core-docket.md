# Authority amendment 003: evidence admission and the small core docket

## Owner correction

Capacity observation 001 satisfies amendment 001's reserved `real host constraint`: one authority case produced 417,174,041 tracked logical blob bytes (397.8 MiB), while a simple lossless gzip estimate was 94,208,279 bytes (89.8 MiB). More importantly, every checkout, Reviewer worktree, scan, backup, and clone pays for indiscriminately promoted execution exhaust. The prior rule that every formal invocation promotes its complete parent event stream is therefore superseded.

**Complete docket** now means a complete, reviewable chain of admitted decisions and supporting evidence. It does not mean a transcript of every token, read result, tool event, duplicated repository byte, or execution detail merely because capture observed it.

## Mandatory core docket

For each caller-designated formal invocation, the tracked core contains only:

1. a versioned manifest with invocation identity, exact caller argv/execution-context identity after credential redaction, package/model/target identity, child and Recorder outcomes, and every admitted artifact path/digest;
2. caller-supplied authority/task/input materials that would otherwise disappear, or resolvable repository artifact references;
3. the mechanically extracted typed role Receipt when one lawful accepted output exists;
4. review reports, finding dispositions, authority amendments, plans, repair artifacts, and closure judgments that participate in the durable decision chain;
5. only the specific exhibits required to substantiate a factual claim or reproduce an accepted behavioral oracle;
6. a redaction report when redaction occurred; and
7. an explicit disposition for every captured candidate that is not promoted when its omission could otherwise make the trail ambiguous.

Store each semantic fact once. A manifest index is not a prose summary, alternate Receipt, role ledger, or trust claim.

## Git is the primary content store

Bytes already recoverable from Git must never be copied into a docket payload. A resolvable reference records repository identity, full commit SHA, repository-relative path, Git blob OID, and SHA-256 of exact bytes. Those coordinates must reproduce the same bytes; the independent digest detects a false or drifting reference. The docket manifest references that one Git object instead of storing another copy.

This applies equally to authority documents, plans, review tasks, Souls, source files, tests, committed fixtures, and any tracked file whose contents reappear inside model/tool output. A session echo or tool `read` of a Git-resolvable file is not a second exhibit and creates no archive entitlement. Decision artifacts created directly as tracked repository files remain at their canonical paths; invocation manifests cite them rather than copy them under each invocation directory.

Dirty, staged-but-uncommitted, untracked, cross-repository-unresolvable, or otherwise byte-unrecoverable inputs cannot masquerade as Git references. If admitted and needed, they are sanitized and stored once as external material; otherwise the invocation archive fails or records a non-promotion disposition as allowed by this authority. Receipt bytes generated by the invocation are stored once because they are not pre-existing repository objects. Cross-repository references require explicit caller selection and do not guarantee future accessibility.

The historical `issue.json` / `materials.md` bootstrap duplication remains preserved evidence of the pre-law process, but v1 must not reproduce that shape for new dockets.

## Raw-session admission

Raw `session.jsonl` is scratch by default, not mandatory tracked history. It may be promoted only when the caller records a concrete admission reason from this exact set:

- the event lifecycle or model-visible exchange is itself the behavioral/provenance proof;
- the lawful Receipt extraction or compliance/method-audit acceptance is disputed and the raw events are needed to adjudicate it;
- the invocation failed in a way whose diagnosis materially depends on raw events;
- the session is an owner-approved recording fixture or otherwise cited exhibit that ordinary repository facts cannot reconstruct.

Curiosity, possible future usefulness, “formal invocation,” and ease of capture are not admission reasons. Admission is caller-owned evidence selection, not model classification and not Recorder judgment. The manifest records admitted/not-promoted status and reason. For a non-promoted session it records sanitized logical byte length and digest only after credential scan, then deletes raw scratch; the digest does not imply retrievability. No transcript summary is generated as a substitute.

## Storage representation after admission

An admitted raw stream remains one canonical logical ordered stream. The package may store it as deterministic losslessly compressed members and/or bounded chunks, provided the manifest records format/version, order, stored and reconstructed lengths/digests, and reconstruction reproduces the sanitized canonical bytes exactly. Manifest, Receipt, decisions, and redaction report remain plain and directly searchable. No lossy summarization, event filtering, reordering, hidden sidecar, Git LFS, content-addressed service, database, catalog daemon, or archive service is authorized in v1.

## Legacy migration correction

The one-time `/tmp` migration applies the same admission law. Migrate decision-chain artifacts and specifically cited exhibits. Do not import raw sessions merely because they exist. For every discovered historical raw session, record one of: admitted with a concrete reason and lossless representation; not promoted with reason and sanitized length/digest; known missing; or excluded as duplicate/reconstructable. Existing issue #10 bootstrap sessions already committed before this amendment remain historical evidence of the capacity failure; they need not be rewritten or copied again. Any repository-history compaction or branch replacement requires separate explicit disposition because deleting files in a forward commit does not remove existing Git objects.

## Preserved boundaries

Recorder remains one opt-in non-role mechanical wrapper around one exact caller-supplied argv command. It does not select, alter, retry, compose, route, judge, summarize, retain by semantic inference, commit, push, or close work. Credential scanning precedes both promotion and digest-only disposition. Unknown credential forms remain outside the bounded scanner guarantee; callers own minimization and rotation.
