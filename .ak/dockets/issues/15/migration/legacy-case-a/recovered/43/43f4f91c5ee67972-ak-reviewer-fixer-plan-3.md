## Investigation

- `HEAD` is clean at `d979a87`, a strict forward descendant of `98f36c0`. Relevant history shows the bypass was introduced with the new provenance bookkeeping in `d979a87`; no older alternative repair exists to reuse.
- Root cause is in `src/role-runtime.ts`: an attempt is appended only inside `Agent.execute()`, while Pi 0.82.1 validates arguments before calling `execute()`. A schema-invalid sibling therefore gets a persisted error result but no `ReviewerAgentAttempt`. The `completed` gate checks only the incomplete attempt array, so an auditor pass can accept the receipt.
- A no-file real-Pi SDK probe confirmed the lifecycle: both `valid-leg` and `invalid-leg` emit `tool_execution_start` while the persisted leaf is the assistant batch; only `valid-leg` reaches `execute`; `invalid-leg` emits `tool_execution_end` with `isError: true` and the validation diagnostic; final tool results persist in assistant source order.
- The existing duplicate-ID and conflicting-batch checks are before child startup, but the tests cover only missing/malformed leaves. The current completion checks also do not mechanically prove a one-to-one match between persisted batch IDs and attempts.
- No Soul or README change is appropriate: this is a mechanical runtime invariant already owned by the Reviewer runtime seam.

## Smallest concrete repair plan

1. **Close the lifecycle gap in `src/role-runtime.ts`.** At Reviewer `tool_execution_start`, capture/reconcile the persisted assistant Agent batch and create at most one running attempt for every Agent ID in that batch, using safe values from the raw arguments. Reuse those attempts in `Agent.execute()` rather than blindly appending. At `tool_execution_end`, settle pre-execution Pi failures as `failed` and preserve the emitted validation text as `diagnostics`; only a child that actually returns successfully may mark an attempt successful.
2. **Make completion independent of the auditor.** Replace the current loose successful-attempt checks with one pre-audit reconciliation: persisted Agent IDs and attempt IDs must be a non-empty exact one-to-one match, with no duplicates, omissions, extras, running rows, or failed rows, and every matched attempt must be successful. Keep provenance failures fatal and before child startup. Do not alter the compliance auditor or receipt schema.
3. **Add focused regressions in `test/reviewer-role.test.ts`.** Add duplicate-ID and conflicting-batch boundary cases that each prove zero child starts, one explicit failed attempt diagnostic, no audit, and no accepted output. Add a real `createAgentSession`/faux-provider Pi case with sibling `valid-leg` plus additional-property-invalid `invalid-leg`; prove both IDs are reconciled, the invalid row is failed with Pi’s validation diagnostic, a `completed` receipt is rejected before an always-pass auditor can waive it, and no completed result terminates successfully.
4. **Verify and commit in apply phase.** Run `npm run typecheck`, the focused Reviewer tests, full `npm test`, `git diff --check`, and `npm pack --dry-run --json` (still exactly the intended 13 packaged files). Confirm the worktree contains only this repair, then create one new forward `fix:` commit without amending `d979a87`, and verify the new HEAD remains its strict descendant.
