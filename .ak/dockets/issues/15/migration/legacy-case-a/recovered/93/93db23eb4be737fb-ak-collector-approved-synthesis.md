**Guard audit required by the repair principles.**
- *Batch gate:* (1) The current Pi core validates each call before `beforeToolCall`; repository test 72 already proves a schema-invalid sibling never enters execute, and `pi-agent-core/dist/agent-loop.js` shows `executionMode: "sequential"` executes an earlier call before preparing the next. Thus a tool-call-only gate misses an all-schema-invalid multiple batch, while sequential mode permits the failure ordering the authority forbids. (2) The finalized assistant message owns batch cardinality; the invocation ledger owns its fatal latch. (3) Removing parallel calls is outside this package and per-call schema cannot express a cross-call invariant. One message-level cardinality check replaces, rather than layers with, B’s sequential mechanism; later checks verify provenance only.
- *Startup/lifecycle latch:* (1) Installed `extensions/runner.js` catches and reports ordinary `session_start` and `input` exceptions, while `print-mode.js` proceeds through supplied prompts. A throw alone can therefore leave startup invalid while provider dispatch continues. (2) The Collector lifecycle controller owns activation validity and terminal process status across `session_start`, first input, and `session_shutdown`. (3) Merely throwing is ineffective at this swallowed seam; argv inspection/wrappers are forbidden by v3. A single fatal state plus handled input/nonzero shutdown is the smallest honest fix.
- *Duplicate-key scan:* (1) Native `JSON.parse` accepts duplicate object members and retains the last value, so schema validation cannot distinguish `{"version":1,"version":2}` or nested/escaped-equivalent duplicates from an unambiguous document. (2) The manifest byte decoder owns JSON lexical identity before parse. (3) Schema-only simplification loses the fact permanently; a bounded duplicate-key lexical scan at that decoder is necessary, not a general parser framework.
- *Detectable instruction-resource check:* (1) Pi exposes custom prompts, append text, context files, skills, selected tools, and commands; a mislaunched ambient resource can instruct the model despite tool narrowing, violating section 5. (2) Startup plus `before_agent_start.systemPromptOptions` owns the supported prompt surface. (3) Documentation alone is insufficient because authority requires detectable launch drift to fail closed. Check only exposed facts; do not add hostile-extension or argv fiction.
- *Request marker/attempt law:* (1) A lost POST response and process restart make an unmarked local success indistinguishable and can duplicate comments; v2 explicitly identifies this race. (2) The request seam owns `(repo,PR,HEAD,leg)` process-local attempts and authenticated exact-marker recovery. (3) Deleting recovery would force either duplicate mutation or false success; global locking is broader and still cannot remove remote response ambiguity. The deterministic marker is the narrow authorized mechanism.
- *Evidence/receipt bounds:* (1) Complete GitHub pages can exceed model/process materialization capacity; truncation would make missing and provenance unverifiable. (2) Atomic snapshot commit owns 8 MiB accounting and ledger/receipt materialization owns 32 MiB accounting. (3) Dropping evidence or truncating is forbidden, so loud pre-commit/pre-output failure is the only simpler safe behavior; no spill/journal mechanism is added.
