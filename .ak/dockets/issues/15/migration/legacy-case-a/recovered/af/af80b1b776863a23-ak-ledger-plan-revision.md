Wave-1 is not yet approved. The extraction boundary is appropriate and proportional, but the proposed contract is incomplete at three behavior-critical seams.

Evidence from current HEAD `380b20515a821d6200625d5cb22cead2b699c25e`:
- `src/role-runtime.ts` returns the settled attempt as Pi Agent `details`; the proposed `completeAgentCall` has no stated return, so the host would have to reconstruct ledger-owned evidence or lose existing package behavior.
- The current prior-infrastructure guard applies before either `completed` or `refused`. The proposal says `recordForAudit("refused")` imposes no requirement and exposes no other health check. That can make a prior fatal Agent/Skill/audit/cleanup failure auditable as a refusal, violating the frozen fatal channel.
- Provenance reconciliation and child execution currently share a catch. With strict transitions, a repeated/cross-batch ID can refer to an already-settled attempt; blindly passing every `beginAgentCall` error to `failAgentCall` would either perform an illegal successful→failed transition or mask the provenance error. The plan does not define atomic failure ownership.
- Several planned “completion-shape” tests are unreachable through the proposed atomic Map-based API without forbidden seeding. Conversely, defensive capture of caller-owned batch, Skill, result, usage, refs, and error evidence is not explicitly tested.
