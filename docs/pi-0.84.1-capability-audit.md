# Pi 0.84.1 capability audit

Issue #225 audit, from the installed 0.83.0 baseline through 0.84.0 and the
0.84.1 patch release. Evidence is the installed `@earendil-works/pi-coding-agent`
`CHANGELOG.md`, its exported types/runtime bytes, and the named repository seams.

| Upstream capability or change | Local disposition | Mapping and behavior evidence |
| --- | --- | --- |
| Host packages and exports | **adapt** | Pi package guidance keeps `@earendil-works/pi-ai`, `@earendil-works/pi-coding-agent`, and `typebox` as optional `"*"` peers, while development snapshots are 0.84.1 / 0.84.1 / 1.3.8 (`package.json`, lockfile). Packed ordinary-npm and real-`pi install` tests prove host runtimes are not privately materialized. The installed `pi-ai` `./compat` export still exists and package tests compile every imported root symbol; **keep and re-audit** that export on the next upgrade. |
| `ModelRegistry.getApiKeyAndHeaders()` nullable `ProviderHeaders` (0.84.0 breaking) | **adapt** | `src/compliance-transport.ts` and `src/navigator-attendance.ts` consume the host registry and preserve `string | null` header deletion markers through `ComplianceDispatch`; typecheck and package tests compile against 0.84.1. |
| `ModelRegistry.refresh(ModelsRefreshOptions)`, runtime-key cancellation, provider publication transaction, OAuth abort signal (0.84.0 breaking) | **keep / no local impact** | Repository search finds no `ModelRegistry` construction, `refresh()`, `setRuntimeApiKey()`, OAuth provider, or handwritten `refreshModels`; contexts only call the host-owned auth methods above. No adapter is warranted. |
| JSON/RPC `message_update` is delta-only (0.84.0 breaking) | **keep / no local impact** | Repository source has no `message_update` consumer and does not assemble RPC partial messages. Role settlement reads authoritative retained session/tool results and terminal `message_end`, so no cumulative-message compatibility layer is needed. |
| `pi auth check` (0.84.1) | **keep upstream; keep local settlement** | The CLI capability is available for human preflight, so no local auth checker is added. It cannot replace per-invocation truth: `src/compliance-transport.ts`, public runners, and settlement still obtain host auth and preserve typed missing-credential/provider failure. The empty-auth public-run tracer covers Pi's zero-exit error path. |
| Blocked extension `tool_call` may return `terminate` (0.84.1) | **keep upstream / no adaptation** | Package submission and compliance tools already return `terminate: true`; the few local `tool_call` observers either collect evidence or perform role-specific preflight and do not implement a blocked all-terminating batch. No retry/termination shim is required. Package/contract tests exercise the terminating results. |
| Fatal provider completion behavior | **adapt** | Pi may emit authoritative `message_end` with `stopReason=error` and exit 0. Shared public settlement records a typed provider failure after excluding lawful terminal and audit-incomplete results; retained auditor evidence wins. The real empty-auth tracer covers this behavior without stderr classification. |
| Canonical launched-Pi identity | **adapt** | `src/public-cli/explicit-internal.ts` has one resolver: relative `PI_BINARY`, relative/empty PATH entries, and version probing use child `cwd`/env; absent PATH uses Node's platform default. It canonicalizes once, probes and launches that same file, then `src/public-cli/invocation.ts` records executable/version in the run's `invocation.json`. Parameterized behavior and ELOOP tests prove lookup semantics and honest canonicalization failure. |
| Test ledger and machine-home isolation | **adapt** | `test/helpers/test-process-fixtures.ts`, shared subprocess helpers, direct Pi harnesses, and `scripts/run-test-all.mjs` use right-hand `undefined` masks for `AK_ROLE_RUN_DIR` and `PI_CODING_AGENT_DIR`; spawn omits them. The real `runExplicitInternalActivation` regression proves a downstream ambient-env merge cannot alter an outer invocation or machine Pi home. Real role evidence therefore records the machine Pi (0.84.1), not a test shim. |
| Codex fast file switch | **keep local pending upstream equivalent** | 0.84.1 accepts explicit `serviceTier` but has no equivalent file switch. `patches/@earendil-works__pi-ai@0.84.1.patch` is the sole patch. Machine 0.84.1 fast-on smoke `resp_0314b23330e8080f016a799a4afd1c819b8805bd096657cac7` completed through `openai-codex-responses` with outgoing `service_tier=priority`. Replace with upstream only when equivalent behavior ships. |
| Direct `pi-telemetry` declaration | **delete** | No repository source imports it; 0.84.0 supplies telemetry transitively. No direct dependency remains. |
| In-process child and nested legs | **keep** | R1 selected `IN_PROCESS_SUPERSEDES_200`. The 0.84.0 experimental remote client/session APIs do not replace that decision; no RPC bridge, private runtime, flag, environment variable, or config is introduced. |
| Remaining 0.84.0 features/fixes | **no local impact** | Fullscreen/TUI mouse/theme/Markdown/Mermaid/LaTeX, context overrides, Baseten, Qwen, custom sampling/vLLM, `AI_AGENT`, deferred requests, agent-harness/session-v4, Bedrock diagnostics, OAuth locking, union coercion, and provider-specific fixes have no package-owned UI, context loader, model catalog/provider registration, remote-session client, or harness-v4 implementation here. Existing host behavior is inherited unchanged. |
| Remaining 0.84.1 features/fixes | **no local impact** | Fullscreen selection/scrolling/theme timing, bash prompt guidance, Bun build flags, TUI wrapper/paste behavior, `Agent.reset()` idle rejection, and rendering fixes do not touch a local API seam. No local mechanism is added. |
