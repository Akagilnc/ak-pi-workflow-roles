# 派单原样透传，文件旗只传路径

Status: accepted

包在调用方与衙门之间只做路由和透传：派单文原样成为衙门的首句，前后不加字、不另存成文件；文件旗（`--attach`、`--prerequisites` 等）只把调用方给的路径原样告诉衙门，包不读、不复制、不校验、不改写；代码不向衙门递自己算出的路径，审核席只得被审腿的身份 `<runId>@<席>`。理由：文件在不在、格式对不对，衙门读得出也处置得了，代码抢先去做只多出一层会坏的加工——受理时的抄件路径在腿归位后即失效。

## Considered Options

- 保留受理时的附件抄件，留一份原样供事后核对——它带出复制、记账、归位时改路径、再传召时再抄、重放时携带一整串，弃。
- 不给被审腿身份，由审核席按票号自找——一张票下同席常有多条腿，既费又可能认错，而包手里有准确身份，弃。

## Consequences

- 各审核席得到被审腿身份的给法统一，修订 [ADR 0079](0079-direct-officer-summons-ticket-memory-pointer-input.md)：所递是身份，不是路径。审核对话原话传递仍依 [ADR 0085](0085-ledger-before-audit.md)。
- 外包手册属启动材料，不进派单文。
- 腿目录里不再有附件抄件与派单文抄件。
