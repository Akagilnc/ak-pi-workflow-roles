# 工厂进度板衙门列道：刑部大列、merge+24h 留存与显示分层

#136 看板初版（卡片堆叠、原始 ms/token 直铺）数据齐全但人扫读不动。2026-08-06 与 owner 的 grill 会话收敛为**衙门列道模型**：列 = 票据当前所在衙门的机械归位，卡 = 票，状态只换色不动窝。本 ADR 记录列模型、归列判据、终态留存与显示分层四条决策；呈现细节（`docs/factory-board-kanban.md`）按锚定宪法可随时重排，`data-*` 契约不变。

## 决策

**列道**：待发 → 大理寺（审票） → 将作监 → 刑部 → 门下省 → 已完成。归列全部机械倒推，无预设流程：

- judge：票无任何已识别非 judge 站 run（未开工）→ 大理寺列；已开工 → 刑部列（判卷）。「开工前过庭」是制度不是判据——#104/#127 实证将作监可直接开工
- coder → 将作监列；fixer / reviewer → 刑部列；collector → 门下省列
- merged（v1 以 issue `closedAt` 为 merge 代理）→ 已完成列

**刑部大列**：御史台/大理寺（判卷）/修内司 三站合一列，卡上以衙门色签区分（颜色 = 衙门，圆点 = 状态）。依据：真卷宗轨迹（#127 七十六卷——将作监×2 后全部在 审→判→修 环内滚动）与 #140 刑部省部级单元设计同构；marshal 落地后其驱动 run 亦归此列（#140 US9 已点名本板消费 correlation）。

**终态留存**：merge+24h 后从板面消失（数据不动，契约全量）；**族共享父票计时**——子票 merge 后常驻陪跑，父票 merge+24h 全家一起退场（父先于子 merge 逻辑上不存在）；点名钻取的关票常驻。

**显示分层**：数据永真全量，默认呈现只摆扫读所需。未知站不做列——右上「未知票 ×N」徽章点击展开（US10 计数诚实归数据层，不绑定呈现）；已交卷待派不做列——卡停最后受理站、蓝点标识；escalate 不动窝——原地换橙色待裁；run 级明细卡内就地钻取。

## Considered Options

- 单票横向地铁路线 / 纵向时间轴 / 衙门纵轴泳道——owner 选定横列左→右流（经典 kanban 手感、全局流向一屏）
- 已交卷待派单列、未知站常驻列、列头成本合计——均被否：前两者违显示分层（非常驻信息不做列）；成本合计因订阅价折扣（luna -80%、k3 $0）算不准，聚合误导
- 族带（每族一行聚合）——被「族筛选下拉」取代：左上项目下拉 + 族下拉（全部/open 父票），默认全部

## Consequences

- 新衙门（太医署、校书郎等环外站）走非常驻列：有票才现身，零配置自动成列
- 列内排序：在飞 → 观察 → 疑挂 → 已交卷，同档末次活动降序（owner：飞的飞完，疑挂自然浮上来）
- v1 merge 标记用 closedAt 代理；真出现「merge 了票没关」实例再升级 PR 关联 mergedAt
