# 中书省是本厂的架构师：出题问宰相，按答案改稿，不判输赢

Status: proposed（2026-10-11，源卷 e4b50c8e，owner uuid `e7598c8d-83c0-4d26-ab2c-a29b7c9be037`、`03700a85-00a0-49c3-ad65-4d983b68ae62`、`b7bb6975-844c-4630-bbaf-48b2bed5e6f8`、`a0fdfadc-4905-4725-9df4-629816e020b4`、`8683b66e-0ab8-4697-8813-680fb45a3774`；待陛下亲审）

中书省的职责与判断方法见 [Soul](../../souls/secretariat.md)，设计尺子见 [《设计法》](../../souls/design-law.md)。本案保留原有交卷闸及给事中、符宝郎审核链，传召关系见 [ADR 0079](0079-direct-officer-summons-ticket-memory-pointer-input.md)。

## Considered Options

- 中书省照旧照派单写票面：它把宰相与陛下的对话整理成票，设计错误原样过庭；#1178、#1199、#1206 都是设计错写进票面、施工后才被陛下问出来，弃。
- 撤掉中书省，由宰相直接送庭：给事中审票面够不够开工、符宝郎审合不合陛下意思，没有一席审设计对不对，弃。
- 中书省自己判胜负、改定稿（决定表）：冻结重放里对的另一做法能被列出，但判胜负时锚在「陛下点过头」与稿子自报的目标上，坏案例几乎全漏，弃。
- 中书省与给事中解绑、只交意见，由宰相改稿后自己送庭：要改传召链与闸代码，弃；保留原闸，改稿交给最懂这张稿的中书省。
- 给中书省一张逐项清单：腿把格子填满、稿子越改越长，真正的设计错一条没抓到，弃。
- 改 Matt 的 `/to-spec`、`/to-tickets` 模板：要加的东西放在中书省，不改外部 skill，弃。

## Consequences

- 中书省会话材料见 [席位注册](../../src/packaged-role-registry.ts)，交卷字段见 [输出契约](../../src/secretariat-contracts.ts)。
- 一张票多一到数轮宰相作答与中书省续审；呈陛下的题会变多，陛下明示多答题的代价小于事后挖改。
- 送庭前三问见 [《票面法》](../../souls/ticket-law.md#送庭前三问owner-2026-09-21)。
- 冻结重放证据（v9–v16，#1199、#1178、#1206 坏案例，#1213 好案例）记在 PR #1218。
