# 中书省是本厂的架构师，审设计不写票

Status: proposed（2026-10-11，源卷 e4b50c8e，owner uuid `e7598c8d-83c0-4d26-ab2c-a29b7c9be037`、`03700a85-00a0-49c3-ad65-4d983b68ae62`、`b7bb6975-844c-4630-bbaf-48b2bed5e6f8`、`a0fdfadc-4905-4725-9df4-629816e020b4`；待陛下亲审）

宰相起草 spec 或票面；中书省是本厂的架构师，开工前审定设计并亲手改定，目标是出好设计——烂的改好，缺的提出好的，错的封还，现有架构该守的守、该破的破。好设计、架构师与好设计稿的标准写在《设计法》（`souls/design-law.md`）。传召链不变：起居郎 → 中书省 → 给事中＋符宝郎。中书省以决定表交卷（`decisions`：稿里每个难改决定、一个截然不同的另一做法、胜负与理由）；陛下点过头的做法不替设计免核，另一做法胜过陛下点过头的做法时两案上呈。

## Considered Options

- 中书省照旧写票面——它照派单把宰相与陛下的对话整理成票，设计错误原样过庭；#1178、#1199、#1206 都是设计错写进票面、施工后才被陛下问出来，弃。
- 撤掉中书省，由宰相直接送庭——给事中审票面够不够开工、符宝郎审合不合陛下意思，没有一席审设计对不对，弃。
- 给中书省一张逐项清单（缺什么、歪什么）——冻结重放里八条腿把清单填齐、稿子越改越长，真正的设计错一条没抓到，弃；改为一把尺（好设计）加决定表。
- 改 Matt 的 `/to-spec`、`/to-tickets` 模板补「替代方案」等节——陛下：「是matt的skill。我不想去加自己的东西。我们需要加的东西应该是在中书省这」，弃。

## Consequences

- 中书省会话材料加入《设计法》与《质量法》；交卷声明增加 `decisions`（只描述，不设类型与必填，原样留存，同 #1134 的声明即校验法）。
- 《票面法》的《送庭前三问》改由中书省执行；第一问定到由包做、由腿做、由哪一席做，再细的接缝留给施工席；给事中引用该问，不另立更细的要求。
- 冻结重放证据（#1199、#1178、#1206 坏案例，#1213 好案例）记在 PR #1218。
