# ADR 0007 的射程限于 Pi 已覆盖的失败类别

Status: proposed（陛下 2026-08-07 立场原话：「删掉是洁癖。保留是容错。」；具体 decision key 待陛下绑定）

**这是对 [ADR 0007](0007-no-audit-retry-brake.md) 末句的具名限缩，不是无声例外。**

被限缩的一句：「传输/调用层重试**复用 Pi 自身机制**（陛下 2026-07-27 补拍）：包内不建任何额外重试包装。」

限缩后加一句：**本句射程为 Pi 已覆盖的失败类别。** `StreamIdleTimeoutError`（流式静默挂死）不在 Pi 的错误路径重试覆盖内——静默超时以本地 signal abort 掉该次请求本身，被本地 abort 的请求不落厂商 SDK 的 `maxRetries`（那条接的是 HTTP 错误）。故包内保留**唯一一层** idle 重交（`DEFAULT_COMPLIANCE_IDLE_MAX_RETRIES`）。**这不是通用重试授权。**

法理是射程不是例外：0007 的立法目的是 DRY，禁的是在 Pi 已有能力之上再叠一份同构物。此处不存在同构物——删掉它，该失败类别没有承接者（CONTEXT.md「承接者判据」）。

四条限定：① 仅 `StreamIdleTimeoutError` 触发；② 不叠第二层；③ 重试用尽仍失败必须如实落痕，不得静默降级；④ 每次 idle 重交须在终局结果中可见（第几次尝试、因何重交）——第 ④ 条不是新护栏也不设墙钟，只让代价可观测：删除总墙钟后每次尝试的时长上限回到厂商 SDK 默认，三次尝试的最坏等待随之上移，必须让人看得见。

将来复核的取数口径（不新建遥测，用现成机器账本）：`StreamIdleTimeoutError` 触发后第 2 或第 3 次尝试最终交出合法决策的次数 ÷ 触发总次数；数据源为既有保留 session 与 `stderr.log`。不预设阈值；若分子长期为 0，届时删除才有实证。

provenance 更正：idle 183s 的 owner-final 归 **#102（2026-08-04）**，#155 是同一 backstop 的另一来源票。两者均晚于 0007 的 2026-07-27——0007 立法时该失败类别尚未被发现。
