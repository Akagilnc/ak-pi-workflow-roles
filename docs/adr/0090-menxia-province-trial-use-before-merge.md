# 门下省改任：替用户覆验交付

Status: proposed（2026-10-22，源卷 e4b50c8e，owner uuid `2c761003-fd2a-48b2-94f2-1d1e595f1e1f`、`8d118d7a-2a59-467e-9302-0a067ad6f735`、`3a4be814-8b55-46f3-91a7-0e167f895a77`、`70a7569a-dbc4-4bf5-a623-dbb343cd8df1`、`118561cb-9c16-4daf-b2a6-b9fd33ae719f`、`38844dad-6044-4504-8edd-1531a7aa9149`；grill 进行中，见 #1243）

测试绿、CI 绿、大理寺收敛之后，仍没有一席站在用户那侧把交付真用一遍；Ming 曾有流程全过、打开游戏却过不了月的事。门下省（gatekeeper）因此改任覆验：到真实入口把交付亲手用一遍，交实录表与三态判词。它只劾不判：实录是证据，修不修、归不归本票由大理寺判。何时传召、与谁并行、判词交给谁，归调用者（[ADR 0010](0010-callers-own-role-composition-and-repetition.md)）；它正适合在通进司等外部评审的那段时间里跑。原「判断该谁审」的职掌作废：交卷闸派官已由代码固定配对（[交卷闸](../../src/submission-gate.ts)），门下省从未坐进闸。

## Decisions

- 输入：票号与工作树（或 PR）指针。用户要什么，门下省自己读票面与起居录里的陛下原话；本仓的用户是谁、真实入口在哪，它从目标仓自己认，overlay 写了就照写的来。
- 范围：验收条是底线，不是边界；验收条未经细磨，不能只照它验。覆验本次改动碰到的全部用户路径。
- 真跑：默认用真实入口、真模型、真服务，花费写进实录；带病发布的代价高于覆验花费。不碰共享状态；要不要另起隔离环境、用哪种入口，由调用者在派单里临时定。
- 现场：门下省从交付的 HEAD 另拉一份工作树真跑，不碰施工工作树；现场留作修理时的证据，到它署（converged）时才清。
- 实录表：放行与封驳都交，是覆验质量的保障；表的样子由冻结重放定，不写进票面。
- 席位：改任落地时门下省改坐 `anthropic/claude-opus-5-5:high`。

## Considered Options

- 门下省坐进交卷闸、由它定派哪些官：在交卷与审核之间多嵌一层，弃。
- 审法（Soul、法条改字的审署）：用得少，不成自动化流程，弃。
- 管上呈（给陛下的题先过门下省）：是司礼监一类的活，目前不需要，弃。
- 合并前查手续（CI、评论线程、能否合并）：不配一个省，通进司与大理寺、修内司已配合得好，弃。
- 合并后验收与收尾：放在合并后才扫尾，挂门下省大材小用，归主簿（#1242）。
- 只照验收条验：验收条未经细磨，抓不到它没写到的坏，弃。
- 调用者在派单里列要验的路径：等于把调用者的判断塞给门下省，成了白名单，弃。
- 放行只交一句话：无从知道它是否真跑过，弃。
- 在施工工作树上跑、跑完即清：清不干净的风险落在修内司那条线上，跑完即删又会在修理还要用证据时删早了，弃。

## Consequences

- 门下省 Soul、交卷字段与 `ak-role help gatekeeper` 随改任重写；旧 [门下省 Soul](../../souls/gatekeeper.md) 与 [交卷指引](../../souls/gate-output-guide.md) 作废。
