# 门下省改任：替用户覆验交付

Status: proposed（2026-10-22，源卷 e4b50c8e，owner uuid `2c761003-fd2a-48b2-94f2-1d1e595f1e1f`、`8d118d7a-2a59-467e-9302-0a067ad6f735`、`3a4be814-8b55-46f3-91a7-0e167f895a77`、`70a7569a-dbc4-4bf5-a623-dbb343cd8df1`、`118561cb-9c16-4daf-b2a6-b9fd33ae719f`、`38844dad-6044-4504-8edd-1531a7aa9149`、`5181528f-9982-4904-8b95-1a87ce81a725`）

测试绿、CI 绿、审核收敛之后，没有一席站在用户那侧把交付真用一遍，Ming 曾有流程全过、打开游戏却过不了月的事。门下省因此改任覆验：到真实入口把交付亲手用一遍、交实录，只劾不判；原「判断该谁审」的职掌作废，因为交卷闸派官早由代码固定配对，门下省从未坐进闸。

## Considered Options

- 门下省坐进交卷闸、由它定派哪些官：在交卷与审核之间多嵌一层。
- 审法（Soul、法条改字的审署）：用得少，成不了自动化流程。
- 管上呈（给陛下的题先过门下省）：是司礼监一类的活，目前不需要。
- 合并前查手续（CI、评论线程、能否合并）：不配一个省，通进司与大理寺、修内司已配合得好。
- 合并后验收与收尾：合并后才扫尾，挂门下省大材小用，归主簿（#1242）。
