# 门下省改任：PR 开出后与通进司并行，替用户覆验交付

Status: proposed（2026-10-22，源卷 e4b50c8e，owner uuid `2c761003-fd2a-48b2-94f2-1d1e595f1e1f`、`8d118d7a-2a59-467e-9302-0a067ad6f735`、`3a4be814-8b55-46f3-91a7-0e167f895a77`、`70a7569a-dbc4-4bf5-a623-dbb343cd8df1`、`118561cb-9c16-4daf-b2a6-b9fd33ae719f`、`38844dad-6044-4504-8edd-1531a7aa9149`；grill 进行中，见 #1243）

测试绿、CI 绿、大理寺收敛之后，仍没有一席站在用户那侧把交付真用一遍；Ming 曾有流程全过、打开游戏却过不了月的事。门下省（gatekeeper）因此改任覆验：PR 开出时由调用者与通进司一并传召，到真实入口把本次交付亲手用一遍，交实录与三态判词。门下省劾而不判：它的实录与通进司收来的证据一样交大理寺判，再由大理寺派修内司。原「判断该谁审」的职掌作废：交卷闸派官已由代码固定配对（[交卷闸](../../src/submission-gate.ts)），门下省从未坐进闸。

## Decisions

- 输入：派单只给票号与工作树（或 PR）指针。用户要什么，门下省自己读票面与起居录里的陛下原话；本仓的用户是谁、真实入口在哪，它从目标仓自己认，overlay 写了就照写的来。
- 范围：验收条是底线，不是边界；验收条未经细磨，不能只照它验。覆验范围以本次改动碰到的用户路径为限。
- 传召：调用者在 PR 开出时与通进司并行传召，包不新增触发点（[ADR 0010](0010-callers-own-role-composition-and-repetition.md)）。
- 真跑：默认用真实入口、真模型、真服务，花费写进实录；带病发布的代价高于覆验花费。不碰共享状态。是否另起隔离环境、用哪种入口由调用者在派单里临时定。
- 实录表：仿符宝郎的条款表，放行与封驳都必须交；没有逐行实录的结论不成立。
- 复验：修完推新提交后，本次改动碰到的用户路径全部重走，不只复验上轮封驳的几条。
- 现场：门下省从 PR 的 HEAD 另拉一份工作树真跑，施工工作树不碰；各轮现场留作修理时的证据，到门下省署（converged）时才由它自己清掉。
- 去向：converged / continue / escalate 三态交调用者；封驳的实录送大理寺判，判定要修再派修内司。修完推新提交，通进司与门下省再并行各跑一轮。
- 席位：改任落地时门下省改坐 `anthropic/claude-opus-5-5:high`。

## Considered Options

- 门下省坐进交卷闸、由它定派哪些官：在交卷与审核之间多嵌一层，弃。
- 审法（Soul、法条改字的审署）：用得少，不成自动化流程，弃。
- 管上呈（给陛下的题先过门下省）：是司礼监一类的活，目前不需要，弃。
- 合并前查手续（CI、评论线程、能否合并）：不配一个省，通进司与大理寺、修内司已配合得好，弃。
- 合并后验收与收尾：放在合并后才扫尾，挂门下省大材小用，另立官职级席位（#1242）。
- 只照验收条验：验收条未经细磨，抓不到它没写到的坏，弃。
- 封驳直交修内司：门下省会走到验收条以外，碰到旧坏或超出本票的行为，修不修、归不归本票该由大理寺判，弃。
- 调用者在派单里列要验的路径：等于把调用者的判断塞给门下省，成了白名单，弃。
- 放行只交一句话：无从知道它是否真跑过，弃。
- 只复验上轮封驳的路径：修一处可能坏另一处，弃。
- 在施工工作树上跑、跑完即清：清不干净的风险落在修内司那条线上；跑完即删又会在修理还要用证据时删早了，弃。

## Consequences

- 门下省 Soul、交卷字段与 `ak-role help gatekeeper` 随改任重写；旧 [门下省 Soul](../../souls/gatekeeper.md) 与 [交卷指引](../../souls/gate-output-guide.md) 作废。
