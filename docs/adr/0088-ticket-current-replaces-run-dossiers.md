# 票一张 current，腿只留宿主原件

Status: accepted（2026-10-08，源卷 d634a8d9，各项 uuid 见 #1197；原件留腿内 2026-10-10，源卷 e4b50c8e，uuid `14b58f6c-a8b2-4a39-abda-c9c637cfff13`；轮的界定、票号写法与续跑默认 2026-11-15，源卷 d634a8d9，uuid `d91600ab-45d6-42e0-a3cc-ed5fd9ad2778`；无票腿不续同日，uuid `25afaa98-84f4-480c-9cd2-ddf394c50e4d`；腿目录三样与回执按到达存 2026-11-20，源卷 d634a8d9，uuid `7bdb2d8f-7173-4c94-9bdd-566371f98b13`、`e70ed947-2dc5-49ba-b050-0fac8bf9b7df`）

名词三个：**进度**＝票目录下的 `current.jsonl`，**回执**＝腿目录里的 `receipts/`，**会话**＝腿目录里的 `session/`。

一张票的进度只有一处：票目录下的 `current.jsonl`，每收下一次交卷追加一行——`at`、`seat`、`round`、`instruction`（本轮传召词原文）、`head`（收下那一刻席位工作树的提交）、`status`、`summary`（20–50 字）、`receipt`（本腿 `receipts/` 里那一份的引用）、`session`（本腿 `session/` 下会话原件的引用）；审官与修内司行另带 `for`（审／修的是谁#轮）。回执是席位交卷的结构化 JSON（findings、decisionGate……，几 KB），一次交卷一份放本腿的 `receipts/`——结论一目了然，不在大文件里翻。交卷一到达就存成这一份：被闸打回的、还没出结果进程就断了的也在里面，照样呈给调用者，文件编号按到达连排；哪份被收下看进度行。这一份是包里唯一的正文——通用提交账对它只记事实与引用、不抄正文，结算读的就是它。本次结论要用的那份读不到，结算失败并报真因；只是更早的一份读不到，本次照常成功，同时报缺了哪份、为什么。太医署自己另存的那一份现阶段不在此列，等该席重新设计时处理。会话是宿主原件，一段对话一份放本腿的 `session/`（[ADR 0086](0086-host-dossier-is-native-file-copy-sitian-append-only.md) 不变：宿主会清理，原件必须复制；pi 的会话文件本身就落在这里），名字只是落点。腿目录留三样：会话、回执、一份包自己的账——只放包续跑和结算离不开的事（宿主会话号、受理时收到的令、施工闸的记号、出错的落痕）。现有每腿 `current.json`／`history.jsonl`／`state.jsonl`／`log.jsonl` 分三步收成这一份（#1298 回执成唯一正文，#1299 没人读的停写、渲染页删除，#1300 并账）。跑完的票目录只有 `current.jsonl`、`records.jsonl`（起居录）与各腿目录。对外地址是「票＋席＋轮」（`ak-role resume 1201 judge`，票号写裸数字），runId 退出用户面。续跑默认续该席在本票下最近活动的那条腿，看腿本身、不看进度表最新一行——行只在收下交卷时写，按行找会漏掉还没交过卷的腿；要点名另一段才写 `<席>#<轮>` 经行定位。还没交过卷的腿没有行，只在它是最近活动的那条时续得到。没报票号的腿不在这个地址里，对外不续、只能新起；包内自动续跑不经这个地址。轮＝一次被收下的交卷，按席在票上累计，御史台两镜分别累计、镜作轮的后缀；审官行在传召那一刻钉死「审 谁#轮」，没被收下的交卷（没交卷被催、被闸打回后重交）不落行、不进轮，已收下的每一份各一行各一轮，续同一段会话再交卷即下一轮。父腿不记子腿指针、不投影他席结论——谁审了谁，只在审官自己那一行。

## Considered Options

- 每腿一套卷宗（current/history/state/log）加父腿指针与他席终局投影（ADR 0075／0079／#753／#1161 的形态）——同一事实多处写，靠绑定保持一致，#1192／#1195 的「取到旧回执」即一致性破裂；14 腿的票要开 14 份 current 才知道进度，弃。
- 宿主会话只记指针不复制——宿主会定期清理，弃。
- 每次起跑存一份系统提示词供事后复盘——陛下从未问过「衙门当时拿到了什么」，发版时间对仓库历史即可还原，弃；行里也不记包版本，`at` 对发版时间即得。
- 回执不另存，要看去会话原件里翻——结论要一目了然，不该在 2 MB 的会话里找一段 JSON，弃。
- 回执等收下才写——交卷过闸前已先落账（[ADR 0085](0085-ledger-before-audit.md)），账只追加不回改（ADR 0086），收下后同一份正文就有两处，中途断掉的稿只在账里；弃。
- 腿目录只留会话与回执两样、包不留自己的账——续跑要的宿主会话号、受理时的令、施工闸记号没有别处可取；弃。
- 腿目录按「席-序号」命名——腿只为承载一段宿主对话而存在，用户面不需要这个概念，弃。

## Consequences

- 三个内部编号的去留不随卷宗自动定：`courtAttemptId`／`invocationScopeId` 在分清哪些交卷、哪些催办属于这一次调用，`attemptHistoryIdentity` 指向每次结算重抄交卷的记录；三步做完后按那时的读者再定（#1202）。太史（analyst）与太医署（doctor）留着、待重新设计（2026-10-08 陛下：「太史留着吧。以后重新设计」），不作读者保护，读不到旧文件是预期。
- 对外地址与续跑默认由 #1201 实现，行上的 `for` 由 #1200 实现。
- 冻结重放改从票级行＋宿主原件重组起跑材料，不再依赖 `turn-delivery`。
- 还没报票号的腿，行与原件先落 `unbound/`，报号后搬到票下（[ADR 0081](0081-diarist-case-context-and-delivery.md) 的角色自报票号不变）。
- 旧格式的 books 不迁移，原样留档；真有必要另立票。
