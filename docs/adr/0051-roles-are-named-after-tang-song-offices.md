## Decision

角色以唐宋官署／官职命名。判据五条：

1. **判据是结构同构，不是职掌精确对上。** 领域可以换：司天不真观天，兰台不真修史。要求的是官署的**权力形状**与席位一致。
2. **不硬凑。** 找不到形状对得上的官，就不取历史名——宁可继续用白话名等下一个候选。
3. **好听是硬尺子，不是加分项。** 名字不好听就没人爱叫，趣味本身属于设计。本裁决曾因此否掉一个更准的候选（见下）。
4. **上奏，不执法。** 监察类席位一旦拿到执法权就是东厂。这条约束优先于任何命名考虑。
5. **不为整齐或成对而造席位、改名。** 名单允许不齐。

朝廷对应：**皇帝＝owner**（authority 唯一来源）；**宰相＝调用者／主 session**（组合角色、定顺序、定何时停，即 ADR 0010 的相权）；**百官＝各角色**。工厂没有政事堂——中枢是 owner，这一格空着是设计正确的表现。

已定名单与各自状态见 [README](../../README.md) 的班子总表。

## Considered options

- **维持白话名（修复工／实现者／评审者…）**：驳回。owner 已定历史命名为方向，白话那批将来迁移。
- **判据取「职掌精确对上」**：驳回。按该判据司天台自己都不合格——它不观天。改采结构同构。
- **同署会暗示上下级，故两席不得同署**：驳回（过度防御）。司天／太史同署也无人以为必须成对调用；出事概率低、后果轻、词表自身会写明可选。
- **合并前另设一席**：驳回（事实不成立）。收线上评审证据、区分 pending／terminal、绑定精确 HEAD 已是 Collector 的现有职掌，该席位早已存在。名字给 Collector，但**不随名字附赠权力**：`门下省` 一名不授予封驳、批准或 merge-readiness 认定——Collector 的 soul 明文「不评审、不裁决、不路由」，其回执报的是收集终态（腿可为 `valid｜unavailable｜missing`），不是「手续齐备」。CI、可合并性与 review thread 是否 resolved **明确不在其覆盖内**（`src/collector-*.ts` 无 `statusCheck`／`mergeable`／`isResolved` 覆盖）；那是功能缺口，另票裁，不得借命名扩权。
- **`详定所`（掌重订官制、删改敕令）给读档议制那一席**：驳回。职掌最准，但不好听——按判据 3，准而不好听等于没人用。改取 `兰台`。
- **`审刑院` 给判官**：驳回（owner 订正）。审刑院复核已断之案而不自断，我们的判官则自行取证（实跑 typecheck/vitest、自建转译与 AST 比对、翻原始 session 记录），是鞫狱定谳，故取 `大理寺`；`审刑院` 归 Soul 合规审计——其「复核程序、不断案」与合规审计的「不得替换判官的实质裁决」逐字对应。
- **`考功司` 给读档议制那一席**：驳回。考功司考的是人（百官功过），我们的席位诊断的是机制。`考功司` 另留给未来的效率考课席（fixer／coder 的具体效率），届时与司天台、兰台构成「记簿→考功→议制」三级。

## Consequences

- **三法司是职责分立的类比，不是流程链。** `御史台`（评审者，劾而不判）、`大理寺`（判官，鞫狱定谳）、`审刑院`（合规审计，复核程序不断案）三者的共同点是「发现问题的人不同时决定怎么办」，与唐宋三法司分立的理由相同。**本 ADR 不规定任何调用顺序，也不设必经链**——组合、顺序、重复次数仍归调用者（ADR 0010）。事实上合规审计并非只跟在判官之后：Judge、Fixer、Reviewer、Doctor 各自都有一次。
- **`审刑院` 不是独立 CLI 角色。** 合规审计是交卷受理前的共享内部接缝，没有 `--ak-role` 标识符，不在角色清单里。当前**只有四个受审角色**各载入一份 role-specific auditor soul：`judge`、`fixer`、`reviewer`、`doctor`（见 `src/auditor-soul.ts` 的 `AUDITOR_SOUL_ROLES`）；`coder`、`collector`、`navigator`、`merger` 没有。
- **只改称谓，不动任何机器可消费的键。** `--ak-role <name>` 的标识符、CLI 参数、工具名（`ak_<role>_output`）、schema 字段一律不变，永远是英文旧名。中文名属**呈现**，标识符属**契约**——按锚定宪法「机器只咬契约，不咬呈现」，改呈现不触发任何迁移，也不需要施工票。既有调用方零改动。
- **`司天台`／`兰台` 只是 [#67](https://github.com/Akagilnc/ak-pi-workflow-roles/issues/67) 已有两席的取名，不扩该票范围。** 且 `司天台` 的席位形态尚未成立——[ADR 0047](0047-sitian-phase-one-mechanism-not-role.md) 已拍定司天第一期是零 LLM 的双面对账机制、**不设 LLM 角色**；本 ADR 只为将来若成席时备名，不推翻 0047。
- **`考功司` 不属 #67。** 该票明示两席，把第三席塞进去是无 authority 的范围扩张。考功司另列为未来留档，需要时单独立票。
- **`弘文馆`（拟给医生）挂起**：医生现有的「病人／症状／方子」医学隐喻仍在使用且好用，为换名而拆掉一套在用的思维工具不划算。名字留档，待医生本身需要修订时再议。
- **`拾遗补阙` 成对留档**，待将来出现第二个进言席再一并启用。
- **真源分工**：本 ADR 持有判据与被否方案（冻结于决策时点）；README 的总表持有当前名单与迁移状态（随进度变化）；CONTEXT.md 在各席位真正落地时才收录术语。三处不得互相复制表格。
