## Decision

角色以唐宋官署／官职命名。判据五条：

1. **判据是结构同构，不是职掌精确对上。** 领域可以换：司天不真观天，兰台不真修史。要求的是官署的**权力形状**与席位一致。
2. **不硬凑。** 找不到形状对得上的官，就不取历史名——宁可继续用白话名等下一个候选。
3. **好听是硬尺子，不是加分项。** 名字不好听就没人爱叫，趣味本身属于设计。本裁决曾因此否掉一个更准的候选（见下）。
4. **上奏，不执法。** 监察类席位一旦拿到执法权就是东厂。这条约束优先于任何命名考虑。
5. **不为整齐或成对而造席位、改名。** 名单允许不齐。

朝廷对应：**皇帝＝owner**（authority 唯一来源）；**宰相＝调用者／主 session**（组合角色、定顺序、定何时停，即 ADR 0010 的相权）；**百官＝各角色**。工厂没有政事堂——中枢是 owner，这一格空着是设计正确的表现。

已定名单与各自状态见 [README](../../README.md) 的班子总表。

## Considered options

- **维持白话名（修复工／实现者／评审者…）**：驳回。owner 已定历史命名为方向，白话那批将来迁移。
- **判据取「职掌精确对上」**：驳回。按该判据司天台自己都不合格——它不观天。改采结构同构。
- **同署会暗示上下级，故两席不得同署**：驳回（过度防御）。司天／太史同署也无人以为必须成对调用；出事概率低、后果轻、词表自身会写明可选。
- **合并前另设一席（曾拟名「门下省」）**：驳回（事实不成立）。收线上评审证据、区分 pending／terminal、绑定精确 HEAD 已是 Collector 的现有职掌，该席位早已存在。CI 与可合并性不在其覆盖内，那是 Collector 的功能缺口，不构成新席位。
- **`详定所`（掌重订官制、删改敕令）给读档议制那一席**：驳回。职掌最准，但不好听——按判据 3，准而不好听等于没人用。改取 `兰台`。
- **`审刑院` 给判官**：驳回（owner 订正）。审刑院复核已断之案而不自断，我们的判官则自行取证（实跑 typecheck/vitest、自建转译与 AST 比对、翻原始 session 记录），是鞫狱定谳，故取 `大理寺`；`审刑院` 归 Soul 合规审计——其「复核程序、不断案」与合规审计的「不得替换判官的实质裁决」逐字对应。
- **`考功司` 给读档议制那一席**：驳回。考功司考的是人（百官功过），我们的席位诊断的是机制。`考功司` 另留给未来的效率考课席（fixer／coder 的具体效率），届时与司天台、兰台构成「记簿→考功→议制」三级。

## Consequences

- **三法司自然浮现**：`御史台`（评审者，劾而不判）→ `大理寺`（判官，鞫狱定谳）→ `审刑院`（合规审计，复核程序不断案）。这不是照抄——三者分立的理由与我们相同：不让发现问题的人同时决定怎么办。
- **现役角色改名要动 CLI 标识符（`--ak-role <name>`）、soul 文件、README 与既有调用方**，因此每个改名各自立票、各自迁移；本 ADR 只确立命名与判据，不授权任何一次改名施工。
- **司天台／兰台／考功司属 [#67](https://github.com/Akagilnc/ak-pi-workflow-roles/issues/67) 的设计素材**，本 ADR 只记录取名结论，不改动该票的设计范围。
- **`弘文馆`（拟给医生）挂起**：医生现有的「病人／症状／方子」医学隐喻仍在使用且好用，为换名而拆掉一套在用的思维工具不划算。名字留档，待医生本身需要修订时再议。
- **`拾遗补阙` 成对留档**，待将来出现第二个进言席再一并启用。
- **真源分工**：本 ADR 持有判据与被否方案（冻结于决策时点）；README 的总表持有当前名单与迁移状态（随进度变化）；CONTEXT.md 在各席位真正落地时才收录术语。三处不得互相复制表格。
