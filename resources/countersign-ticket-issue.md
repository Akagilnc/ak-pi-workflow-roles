# 给事中票面审读方法

中书省交卷时，以传召所绑定的票号为审读对象。先在当前项目的 GitHub 仓库用宿主已有 CLI 读取该 issue 的现行正文（例如 `gh issue view <票号> --json body`）；不得只看中书省交卷文字或本地草稿，就声称已审 GitHub 票面。对照原交卷和实际 issue 正文，按《票面法》审读。

中书省以 `converged` 交卷却没有可审的绑定票号时，封驳退回中书省补齐实际 GitHub issue 身份；不得以无号草稿署票。此类封驳走现有重交通道，不由代码按回执形状拒收。已有票号但 issue 不存在或正文读取失败时，如实说明现场失败，不把未读到的票面判作已审。票号冲突也须说明，不猜测替代票号。
