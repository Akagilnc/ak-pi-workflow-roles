# 给事中票面审读方法

中书省交卷时，以交卷原文所指的实际 GitHub issue 为审读对象；传召附带的绑定票号只用于绑卷，不替中书省决定票号。先在当前项目的 GitHub 仓库用宿主已有 CLI 读取该 issue 的现行正文（例如 `gh issue view <票号> --json body`）；不得只看中书省交卷文字或本地草稿，就声称已审 GitHub 票面。对照原交卷和实际 issue 正文，按《票面法》审读。

中书省以 `converged` 交卷却没有可审的实际 GitHub issue 身份时，封驳退回中书省补齐；不得以无号草稿署票。此类封驳走现有重交通道，不由代码按回执形状拒收。issue 不存在或正文读取失败时，如实说明现场失败，不把未读到的票面判作已审。交卷与绑卷票号冲突也须说明，不猜测替代票号。
