# 中书省票身份与落票方法

本方法适用于公开中书省调用。票面范围、审读职责和交卷形状仍以各自法源为准。

## 先辨票，再改票

调用者可以给票号，也可以不给。给了票号，先读取并核对该 issue，再在原 issue 上更新票面；不要另建一票。没有给票号，不等于新票：先结合本次对话、本票起居录和当前 GitHub 仓库中的 issue 判断是否已有对应票。找到已有票就更新那张；只有确认没有对应票，才在当前仓库创建 issue。不得仅凭内容相似就认定已有票，也不得因没找到就忽略搜索范围或不确定性。

票面改定后，应将实际要执行的正文落到对应 GitHub issue。不能确认已有票还是新票、无法读取或更新目标 issue，或创建 issue 失败时，不得把草稿当成已落票结果送庭；应上呈并说明现场观察到的真实失败原因。若信息不足以区分多个候选 issue，也上呈请裁定，不猜票号、不另建重复票。

## 落地后送庭

只有确认目标 issue 存在且正文已更新为本票最终票面后，才以 `converged` 交卷，并携带该 issue 的实际票号。沿用既有交卷闸，由给事中审这张有票号 issue；不以无号草稿替代 issue 审读。票号由交卷闸和既有起居录流程沿用，不另造传召或记账机制。

执行 GitHub 操作时使用当前宿主实际提供的 CLI / 能力；不在包内另造 GitHub 适配层。记录足以核对身份和落地结果的证据，不把模型自报冒充为现场观察。
